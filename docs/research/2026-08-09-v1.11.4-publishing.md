## Question

Can the existing tag-triggered `publish.yml` and Registry metadata publish
`@xzxzzx/bilibili-mcp@1.11.4` without a workflow or package-ownership change?

## Findings

- `.github/workflows/publish.yml` already runs on GitHub-hosted Ubuntu, grants
  `id-token: write` and `contents: read`, uses Node `22.14.0`, installs npm
  `11.18.0`, and publishes with provenance. Those values meet the current
  documented minimums, so no workflow edit is required for this patch release.
- The workflow is tag-triggered. The annotated `v1.11.4` tag must therefore
  point at the release commit containing all five `1.11.4` version fields; a
  tag on `1067e02` would attempt to republish immutable `1.11.3`.
- Trusted publishing produces short-lived OIDC credentials. No npm token should
  be added to the repository, release notes, local QA, or workflow.
- npm trusted publication precedes Official Registry publication. The Registry
  stores metadata and validates the public npm package's `mcpName` against
  `server.json.name`.
- The current publisher CLI documentation exposes no standalone `validate`
  command. Before npm publication, validate the manifest against its live
  schema; after npm `1.11.4` is public, use the authenticated `publish` command
  and verify the Registry API result.
- `server.json` remains a repository-root publisher manifest and is not in the
  npm tarball by existing design. The npm tarball includes `package.json` with
  the matching ownership field.

## Decision Impact

- Keep `publish.yml`, Action pins, dependencies, and package layout unchanged.
- Use only the controlled release commit -> annotated tag -> Actions/npm ->
  exact-version verification -> GitHub Release -> Registry sequence.
- Do not use `publish.bat` (hard-coded `v1.1.0`), `npm run release`, direct local
  `npm publish`, or pre-version `workflow_dispatch`.

## Risks And Staleness

- npm versions and tags are immutable; after tag publication, rollback means a
  forward patch release rather than replacing `1.11.4`.
- Registry namespace matching is case-sensitive. Preserve
  `io.github.XZXZZX-Ai/bilibili-mcp` exactly.
- Refresh this note if the workflow, trusted-publisher configuration, npm/Node
  minimums, Registry schema, publisher commands, or package layout changes.
