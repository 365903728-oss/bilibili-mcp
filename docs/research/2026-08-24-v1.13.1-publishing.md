# Research Note: v1.13.1 npm, GitHub, And Official MCP Registry Publishing

## Research Topic

- Date: 2026-08-24
- Owner: Codex
- Related ticket: `REL-2026-08-24-V1.13.1`

## Question

Can the unchanged tag-triggered workflow publish `1.13.1` through npm trusted
publishing, and can the matching manifest then update the Official MCP Registry?

## Sources

| Source | Type | Date checked | Relevant finding |
|---|---|---|---|
| https://docs.npmjs.com/trusted-publishers/ | official npm docs | 2026-08-24 | GitHub Actions trusted publishing uses OIDC, requires `id-token: write`, and automatically creates provenance for public packages from public repositories. |
| https://docs.github.com/en/actions/how-tos/secure-your-work/security-harden-deployments | official GitHub docs | 2026-08-24 | OIDC avoids long-lived deployment credentials and requires an explicit token permission. |

| https://github.com/modelcontextprotocol/registry/blob/main/docs/modelcontextprotocol-io/github-actions.mdx | official MCP Registry docs | 2026-08-24 | Registry publication must follow publication of the underlying npm package and may use GitHub authentication without storing package credentials. |
| `.github/workflows/publish.yml` | repository source | 2026-08-24 | Tag-only GitHub-hosted Node 22.14.0 job, npm 11.18.0, `id-token: write`, tests, build, and public provenance publish. |

## Findings And Decision

- The existing workflow still meets the current npm trusted-publishing OIDC and runtime requirements; no npm token, workflow, action revision, or dependency change is needed.
- Keep the annotated tag immutable and push it only after local release verification and a fast-forward release commit on `master`.
- Wait for npm exact/latest plus provenance before creating the final GitHub Release or publishing `server.json` to the Official MCP Registry.
- `package.json.mcpName` and `server.json.name` already match the case-sensitive namespace `io.github.XZXZZX-Ai/bilibili-mcp`; only the two manifest version fields change.
- Use the current official Publisher to validate before publication. Authentication may be refreshed interactively if the saved value-free session is expired; credentials and device codes must not be recorded.
