## Findings And Decision

- The existing workflow still satisfies the current trusted-publishing runtime and OIDC requirements.
- No npm token, dependency update, or workflow change is required.
- Push the annotated tag only after local release verification; create the GitHub Release only after the tag-triggered npm publication succeeds.
- The initial release scope excluded the Official MCP Registry; the user's later explicit authorization added only the matching Registry publication.
- Existing `server.json` and npm `mcpName` already match the case-sensitive namespace `io.github.XZXZZX-Ai/bilibili-mcp`, so no package or workflow change is required.
