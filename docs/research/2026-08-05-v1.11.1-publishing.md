## Question

Does the current tag-triggered `.github/workflows/publish.yml` still satisfy the
current official GitHub Actions tag-filter rules and npm trusted-publishing and
provenance requirements for publishing `v1.11.1`, or does it need a change?

## Context

Why this matters for `@xzxzzx/bilibili-mcp`:

- The workflow publishes only when a `v*.*.*` tag is pushed, so the tag's target
  commit determines the published version. A tag created before the version
  bump would attempt to republish `1.11.0` instead of `1.11.1`.

What decision or implementation this may affect:

- Whether the `v1.11.1` tag-triggered trusted publication can proceed with the
  workflow unchanged, and how Codex should verify the publication chain.

## Findings

- The workflow triggers on `push.tags: 'v*.*.*'`; in GitHub filter patterns `*`
  matches zero or more characters (but not `/`), so `v1.11.1` matches and a
  plain push to `master` without a tag does not start publication.
- npm trusted publishing currently requires npm CLI 11.5.1+ and Node 22.14.0+,
  and a GitHub Actions workflow with `id-token: write` plus `contents: read`.
- The workflow already uses Node `22.14.0`, installs npm `11.18.0`,
  `permissions: id-token: write` / `contents: read`, runs `npm ci`, tests,
  build, and `npm publish --provenance --access public` on a GitHub-hosted
  runner — satisfying the documented minimums and the OIDC boundary.
- Provenance applies automatically under trusted publishing for public
  repositories publishing public packages; the explicit `--provenance` flag is
  compatible with that behavior.

## Applicability To This Project

Applies:

- The existing tag-triggered workflow can publish `v1.11.1` unchanged.
- The annotated `v1.11.1` tag must point at the release commit that contains
  the `1.11.1` package metadata (after the version bump), so the tag-triggered
  run publishes `1.11.1`, not `1.11.0`.

Does not apply:

- No workflow, action version, dependency, token, or provenance change is
  needed; a workflow edit is out of scope for this release.

## Decision Impact

Recommended project action:

- Keep `.github/workflows/publish.yml` unchanged; push the release commit and
  annotated tag `v1.11.1` only after the version bump is committed.

Rules or files that may need updates:

- None for this release. Any future workflow edit must refresh this research.
